* Why compare tools
:PROPERTIES:
:BEAMER_opt: pg=2
:END:
#+beamer: \slidegraphics{figures/workflow-alternatives/gtext}
#+attr_latex: :options [x=80,y=140,s=22,l=32,ind=26,bf=arial,w=780,p=5]
#+begin_tb
- Many small tasks inside one Slurm allocation need a tool that starts a task as soon as a core is free.
- QCG-PilotJob is one such tool. HyperQueue, Snakemake and FireWorks are three others.
- Each one expresses ``this task waits for those tasks'' differently.
- The comparison: how the dependency is written, and how much of the allocation sits idle.
#+end_tb

* What the idle time comes from
:PROPERTIES:
:BEAMER_opt: pg=9
:END:
#+beamer: \slidegraphics{figures/workflow-alternatives/gtext}
#+attr_latex: :options [x=80,y=140,s=20,l=28,ind=26,bf=arial,w=790,p=8]
#+begin_tb
- The bash pipeline runs tasks in blocks of the slot count, so a block waits for its longest task.
- QCG-PilotJob: 7%, a second at the start, three at the end, short gaps between tasks. With a module load in every task an earlier run showed 23%; the examples leave *modules* out.
- HyperQueue: 2%, the next task starts when a slot frees up. Snakemake: the same between tasks, but 77 s of its own start-up before the first one, so 32%.
- FireWorks: one worker on a file LaunchPad, so the tasks run one after another: 344 s.
- Plot lanes show the CPU number a task reported at start. Tasks are not pinned, so overlapping bars can leave white space that is not idle time.
- The idle figure comes from the task start and end times.
#+end_tb

* How to choose
:PROPERTIES:
:BEAMER_opt: pg=10
:END:
#+beamer: \slidegraphics{figures/workflow-alternatives/gtext}
#+attr_latex: :options [x=80,y=145,s=24,l=34,ind=28,bf=arial,w=780,p=12]
#+begin_tb
- *QCG-PilotJob* and *HyperQueue*: many tasks inside one allocation. QCG-PilotJob is driven from Python; HyperQueue from the command line, with a Python API as well.
- *Snakemake*: rules on files; a rerun builds only what changed.
- *FireWorks*: a database of workflows with states and reruns. Without a MongoDB server the file LaunchPad allows one worker: 212 s for 1000 averages on one core on Snellius, against Snakemake's 15 s on 16 cores; alike per core, but FireWorks cannot take more cores.
#+end_tb
